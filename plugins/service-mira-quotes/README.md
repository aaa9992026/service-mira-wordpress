## Financial configuration

Observed rates: Unterhaltsreinigung, Einkaufshilfe, Gartenarbeit, Haushaltsreinigung and Treppenreinigung each 1750 cents/hour. These are seeded as **unconfirmed**. Other services have `cents: null` until confirmed. Existing page content is never changed, including other published prices. Admin catalog supports up to 50 hourly/fixed-basis services, nullable integer cents, a `confirmed` boolean and exact `scope`. Variable quotations need individual scope/pricing review; do not mark them confirmed merely to bypass the gate.

`vat_mode`: unknown, net, gross or exempt. `vat_bps`: basis points, blank = unknown. `fee_cents`: aggregate fixed fee per quote in the **same** tax basis as the hourly rate; blank = unknown, explicit 0 = confirmed no charge. `fee_label`: complete fee/travel rule description. `minimum_units`: quarter-hours (1 = 15 minutes); blank = unknown. Limits of 0.25–100 hours are technical input bounds, not a business minimum. New links expire after a configurable 1–720 hours (default 72, a technical validity default). Monetary calculations round half up to integer cents; tax is calculated once on the total including fees. Gross mode derives net and sets tax to gross minus net. Tax-exempt status/reason must be approved in the terms. Multiple tax rates or tiered/distance pricing are not implemented: keep those offers unconfirmed.

## Rollback and retention

On staging, turn off test acceptance first; pending snapshots cannot be accepted while that switch is off. Deactivate the plugin and remove its shortcode from the new test page. Deactivation/deletion intentionally retains the custom quote table and settings; no uninstall purge runs. Back up records before any explicit deletion. Use quote details for per-record deletion after retention review, or WordPress verified privacy requests. Privacy erasure removes pending records and flags accepted evidence for manual retention review; this is a workflow choice to review with the client, not a statement of legal retention requirements. No automatic quote-retention duration is invented.

Switch back to the original parent/previous child on staging and restore its theme_mods, menus and widgets from the staging snapshot. If required, restore the **staging-only** backup following the host/WP STAGING procedure. Never restore staging tables over production. Remove the staging-only mail constants only when the host has a separate safe mail block in place, or leave delivery blocked. Restore noindex/access controls if another component changed them. WP salts protect snapshot authenticity: changing salts intentionally invalidates existing snapshots; preserve salts securely in staging backup and never copy production secrets into source.

Build artifacts with `powershell -ExecutionPolicy Bypass -File tools/build.ps1`. It creates both component ZIPs, a source handoff and SHA-256 checksums. No deploy/publish/push command exists in the build. No credentials or local runtime database belong in the artifacts.
